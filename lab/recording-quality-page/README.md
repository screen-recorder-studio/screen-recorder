# Recording Quality Test Page

零依赖、零网络请求的屏幕录制质量测试卡。它只用于发布前端测，不参与扩展构建或生产代码。

## 启动

可以直接用 Chrome 打开 `index.html`。为避免 `file://` 环境差异，也可以在此目录启动任意静态服务器：

```bash
cd lab/recording-quality-page
python3 -m http.server 4173
```

然后访问 `http://localhost:4173`。保持 Chrome 页面缩放为 100%，并分别测试“标签页”“窗口”“整个屏幕”录制方式。

## 覆盖项目

- 静态防形变：120 × 120 正圆和正方形、16:9 与 1:1 参考框、中心线和 90% 安全区。
- 清晰度：原生未变换的 1px 横竖线、24px/6px 网格、中英文与 12px/16px/28px 文字、1px 轮廓文字。
- 色彩：八段高饱和色条和八段灰阶。
- 运动：6 秒匀速往返、1.2 秒快速往返、3 秒连续旋转。
- 合成与缩放：`translate`、`scale`、`rotate`、`skew` 组合的 CSS transform。
- 时序：毫秒计时器、累计 `requestAnimationFrame` 帧数和约 500ms 窗口统计的页面 FPS。
- 动画暂停对照：“暂停动画”只暂停测试区的运动动画；毫秒计时器、页面 FPS 和累计帧数继续更新，因此页面仍会持续产生像素变化。
- 真静态对照：“冻结画面”暂停页面上的全部 CSS 动画，并停止计时器、页面 FPS、累计帧数和 Viewport 文本的 DOM 更新。冻结期间页面像素保持不变，用于静态画面/0Hz 录制验证；解除冻结后计时器会按真实经过时间向前跳转，不会倒退。

## 建议端测流程

1. 开始录制后保持动画运行 10 秒，观察匀速球、快速球、旋转轮和变换卡片。
2. 点击“暂停动画”录制 5 秒。确认测试动画停止，但页头计时器、FPS 和帧数仍持续更新；随后点击“继续动画”。
3. 点击“冻结画面”录制至少 10 秒。不要移动或缩放窗口，确认所有动画和三个数字读数均完全静止，以形成真正静态/0Hz 对照段。
4. 点击“解除冻结”，确认计时器向前跳到实际已经经过的时间，且动画、FPS 和帧数更新恢复；继续录制 5 秒后结束。这样得到完整的“动 → 静 → 动”样本。
5. 在编辑器预览和最终导出文件中逐项比较：
   - 圆是否仍为正圆，16:9/1:1 框是否无拉伸；
   - 1px 线是否消失、闪烁或变为双线；
   - 网格是否产生明显莫尔纹，文字边缘是否发虚；
   - 色条和灰阶是否截断、偏色或出现 banding；
   - 匀速运动是否周期性顿挫，快速运动是否有严重块效应；
   - 旋转与 transform 边缘是否撕裂；
   - 录制时长是否与页面计时器的真实经过时间一致，“暂停动画”段和“冻结画面”段是否都被完整保留；
   - 冻结段是否只保留单帧/极低帧率，解除冻结后时间轴是否继续向前且没有倒退。

建议至少覆盖 1280×720 和 1920×1080 两种输出，并记录浏览器缩放、设备像素比、录制方式、编码格式和导出配置。
