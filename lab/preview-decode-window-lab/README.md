# Preview Decode Window Lab

这个 Lab 固定复现真实 Slice 链路的容量错位：Reader 从关键帧 180 开始返回 140 个编码块，目标可见帧是 241，而高分辨率预览只允许保留 30 个解码帧。

- 旧策略在容量满时删除最早帧，最终数组实际是 290–319，但窗口仍宣称从 241 开始；请求局部帧 0 会错误显示全局帧 290。
- 修复策略只把 180–270 的 91 个必要块送入解码器，丢弃 180–240 的解码预卷，固定保留 241–270；Reader 其余 49 个尾块不再做无效 4K 解码，请求局部帧 0 精确显示全局帧 241。

从仓库根目录启动现有 Vite Lab 服务，打开：

```text
http://127.0.0.1:4179/lab/preview-decode-window-lab/
```

验收要求：默认案例显示“通过”，实际送入解码器为 `91/140`，且修复策略的窗口起点、局部帧 0、实际全局帧三者均为 241。
