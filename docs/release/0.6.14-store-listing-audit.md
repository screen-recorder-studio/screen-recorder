# Chrome Web Store 0.6.14 商品详情审计

审计日期：2026-08-30  
线上版本：0.6.12  
候选包：0.6.14（由 0.6.13 功能候选升版；同步 54 个 locale 的标题与摘要）

## 结论

0.6.14 提审前需要同步优化商品详情。线上说明和五张截图仍以 0.6.12 的通用录屏工作流为主，没有呈现本期最有辨识度的“网页区域 → GIF → Studio”闭环；首张截图还展示了旧版 Action 页面结构，与候选版本不一致。

本轮应完成两类修改：

1. 必须：更新英语、简体中文、繁体中文和俄语的详细说明；替换四种语言各五张本地化截图，并以英语截图作为全球回退。提审校验另提示菲律宾语、印地语、克罗地亚语和斯瓦希里语元数据不一致，因此也补齐了这四个语言的详细说明。
2. 建议但会改变候选包：更新 Manifest 中 54 个 locale 的标题/摘要，将搜索首屏定位从“Unlimited / Zoom”收敛到“Area & GIF Recorder”。Chrome Web Store 要求包内元数据变更使用更高版本号，因此这项修改需要把候选版本升到 0.6.14、重建、回归并重新上传。

本轮已选择路径 B：候选版本升到 0.6.14，同步 54 个 locale 的标题与摘要，并重新构建、回归和上传；最终保存八份详细说明与四套截图。

最终结果：提审校验警告已消除，0.6.14 于 2026-08-30 成功提交审核，当前为“待审核”，并启用审核通过后自动发布。

## 发现的问题

### 1. 搜索首屏定位落后于产品

当前英文标题为 `Screen Recorder Studio - Unlimited, Zoom, Video & GIF`，摘要强调不限时长、缩放、裁剪和 MP4/GIF。它们仍然真实，但没有说明本期最有区分度的区域 GIF 工作流，也没有 WebM、本地处理和 Studio 成品化能力。

建议标题：

`Screen Recorder Studio – Area & GIF Recorder`

建议英文摘要（126/132）：

`Record a page area as GIF, or capture tabs, windows, and screens. Edit locally, then export polished MP4, WebM, and GIF files.`

建议简体中文标题：

`Screen Recorder Studio - 区域录屏与 GIF 制作`

建议简体中文摘要：

`框选网页区域直接录制 GIF，也可录制标签页、窗口或全屏。本地裁剪、缩放与美化，一站式导出 MP4、WebM 和 GIF。`

### 2. 线上详细说明未覆盖本期能力

当前详细说明仍包含“Version 0.6.12 improves...”段落，且把区域录制仅写成 Studio 内的裁切能力。建议删除易过时的版本改进清单，把首段改为明确的用户结果，并按以下顺序组织：

1. 选中网页重点区域并录制短 GIF 流程
2. Tab / Window / Screen 标准录制
3. Studio 修剪、裁切、缩放、背景与构图
4. GIF 邮件导向预设和体积建议
5. MP4 / WebM 交付
6. 本地存储、无媒体上传和开源可信度

拟写文案见 `release-assets/0.6.14/store-copy/`。

### 3. 截图已过期且首屏价值顺序不佳

现有五张截图分别展示旧 Action、时间线、导出、裁切和本地录制库。整体风格统一，但存在以下问题：

- 首张是 0.6.12 旧 Action，未显示“Record GIF”入口；
- 新增 Area 选择过程完全缺席；
- GIF 仍只是第三张导出弹窗中的一个标签，未成为首屏任务；
- 截图中的版本号和部分 Studio 结构已过期；
- 强荧光绿色背景抢夺注意力，产品 UI 在缩略图中偏小；
- 商店后台同时配置本地化截图和全球截图，英语用户可能看到重复素材序列。

建议的新五图顺序：

1. `Record a page area. Export a focused GIF.`：新 Action + 区域框选状态
2. `Polish the flow in Studio.`：新 Studio、时间线、裁切/缩放/背景控制
3. `GIF settings for email-sized demos.`：600/480/320 px、帧率、有限循环与体积提示
4. `Export MP4 or WebM when video fits better.`：统一导出弹窗的视频格式与质量选项
5. `Private by design. Stored locally.`：新 Recording Manager 与本地录制库

每张图应使用 1280×800、全出血、方角、最新 0.6.14 UI，并确保在缩小到 640×400 时仍能读懂。四种语言继续沿用英语、俄语、简体中文、繁体中文的本地化资产策略；其他 50 个 locale 使用英语全球回退。

### 4. 需要明确的能力边界

商品详情不得承诺尚未交付的能力：

- 不写“自动保证 1 MB 邮件 GIF”；当前提供的是邮件导向默认值、体积估算和风险提示；
- 不写 Landing Motion Pack、Poster、嵌入代码或 fallback PNG；
- 不写 Element Capture；0.6.14 的公开路径是固定视口区域；
- 不写云上传、云分享或托管；录制、编辑和导出是本地工作流；
- 不把长 GIF 描述为稳定默认场景；应提示长或高运动 GIF 需要裁短或降低输出设置；
- 区域选择仅适用于 Chrome 允许注入的普通网页，受限页面会安全拒绝。

## i18n 策略

- 包内：54 个 locale 的标题与摘要保持完整；若本轮更新搜索定位，应一次性同步 54 份 `appName` / `appDesc`，避免混合新旧定位。
- 商品详情：更新四个高维护质量 locale（en、ru、zh-CN、zh-TW）；为消除包内元数据与商品详情不一致警告，同时补齐 fil、hi、hr、sw，其他语言继续使用英文默认说明。
- 截图：四个本地化集合各五张；英语另设全球回退。上传后逐张复核截断、录制/录音术语和繁简体用字。
- 产品内：0.6.14 的 en/zh-CN 新结构字符串已完整，其他 52 个 locale 对新增界面键使用英语回退；包内 54 个 locale 的商店标题与摘要已单独同步，不应表述为 54 种语言均已完整翻译全部新界面。

## 推荐发布路径

### 路径 A：保持 0.6.13（较低发布风险）

更新四份详细说明和四套截图，保留当前包内标题/摘要。完成商店草稿保存和公开预览复核后提审。

### 路径 B：升到 0.6.14（较高转化潜力）

同步 54 个 locale 的标题/摘要，版本升到 0.6.14，重建并执行自动化门禁及关键浏览器回归，再上传新包并应用详细说明和截图。

建议采用路径 B。当前商品页只有约 1.8% 的展示进入详情，标题与摘要位于搜索和分类页首屏；只更新长说明无法改善这一步。同时，旧截图与新 UI 不一致已经构成必须修正的陈旧元数据问题。
