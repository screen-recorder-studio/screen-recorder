# Studio 与弹窗视觉统一评估

## 结论

本次统一是合理且应当完成的发布前切片。`video-record` 当前 Studio 的核心问题不是单个颜色或圆角，而是视觉模型仍属于浅色网页表单：白色顶栏、白色属性卡片、较重的灰色边框以及多个彼此独立的弹窗样式。`chrome-covers` Studio 已形成更完整的创作工具语言，适合作为同一产品族的基准。

本切片只统一信息层级、布局几何、控件状态和弹窗框架，不改变录制、OPFS、预览解码、时间线、裁剪、Zoom 或导出业务逻辑。

## 端到端差异

### Studio 壳与顶栏

现状使用浅灰页面和白色顶栏，品牌、比例控件与外链按钮呈现为普通网页导航。目标改为深色 56px 创作工具顶栏：左侧产品与状态，中间比例分段控件，右侧低噪音辅助入口。试用标识沿用参考工程的琥珀金属徽章，GIF 身份使用紫色但不与主导出操作争抢层级。

### 预览与时间线

预览区域本身已是深色，但与页面壳、控制条和时间线存在多套 gray 色阶。目标统一为 zinc 层级，并降低边框、阴影和按钮装饰强度。播放是唯一圆形高强调操作；Trim、Zoom、Crop 使用紧凑的抬升表面。

### 属性栏

现状 400px 白色侧栏包含四张独立白卡，信息密度与参考工程不一致。目标为 320px zinc-900 属性栏，顶部固定操作区，内容滚动；背景、圆角、内边距和阴影改为同一套暗色卡片与分段控件。

### 弹窗

导出、Drive 与删除确认目前各自定义白色弹窗。目标统一为同一框架：70% 黑色模糊遮罩、zinc-900/95 面板、`white/10` 边界、渐变顶栏、固定页脚。关闭、Escape、焦点陷阱、导出取消和删除确认行为保持原样。

## 风险与控制

- **320px 侧栏容量**：颜色网格必须使用流式单元而不是固定 32px，避免横向溢出。
- **头部碰撞**：比例控件保持紧凑，辅助链接允许隐藏文字或在较小宽度收缩。
- **暗色表单可读性**：输入、选择框、开关与范围控件必须同时有边界、焦点环和禁用态，不能只依赖颜色。
- **GIF 层级泛化**：紫色只用于 GIF 语义；MP4/WebM 和共享编辑操作继续使用蓝色。
- **业务回归**：视觉迁移不改组件事件、store、worker 消息或 OPFS 数据结构；以既有单测、类型检查、生产构建和真实扩展浏览器验证共同兜底。

## 发布验收

- Studio 首屏、加载态、空态和有录制态均无浅色孤岛。
- 1440×900 及更窄窗口下，顶栏无碰撞，右侧栏无横向滚动。
- 比例、背景、圆角、内边距、阴影、播放、Trim、Zoom、Crop 均保持可操作。
- 导出弹窗的 MP4、WebM、GIF 标签与内容状态清晰，GIF 使用紫色语义。
- 导出进度、错误、取消，Drive 列表与删除确认均符合统一弹窗框架。
- 键盘焦点可见，Escape、Tab 循环、关闭与返回焦点行为无回归。
- 全量测试、`svelte-check`、生产扩展构建通过，并在隔离浏览器中完成视觉与交互修正循环。

## 实施结果（2026-08-24）

本切片已完成，覆盖 Studio 有录制态、加载态、空态、编辑面板、时间线、导出弹窗、Drive 弹窗与删除确认。实现包括：

- 建立受 `.studio-theme` 约束的 Studio 视觉变量与组件类，避免影响 Popup、Side Panel 等非 Studio 页面。
- 将应用壳、56px 顶栏、320px 属性栏、预览工作区和时间线统一到 zinc 深色层级。
- 将比例、背景、圆角、内边距、阴影、裁剪和 Zoom 控件统一为紧凑创作工具样式，并补齐 `aria-pressed` 等状态语义。
- 将导出、Drive 和删除确认统一到同一弹窗框架；导出保留蓝色通用语义和紫色 GIF 语义。
- 为导出和 Drive 弹窗保留或补齐焦点循环、Escape 关闭、嵌套确认的安全初始焦点及关闭后的焦点恢复。

浏览器修正循环发现并关闭了三个发布前问题：

1. 320px 属性栏中的背景标签会横向溢出：非激活标签改为仅显示图标，激活标签显示文字，网格改为流式布局。
2. GIF 录制身份将紫色错误传播到 Crop、Zoom 等共享编辑操作：Studio 根强调色恢复为蓝色，仅 GIF 标记和 GIF 导出局部使用紫色。
3. 嵌套删除确认最初未进入 Edge 无障碍树：确认期间将外层 Drive 面板设为 `inert`/`aria-hidden`，焦点进入 Cancel，关闭后回到原 Delete 按钮。
