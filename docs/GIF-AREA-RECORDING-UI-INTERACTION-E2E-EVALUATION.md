# GIF 区域录制 UI / 交互端到端评估

> 评估日期：2026-08-24
> 基线版本：0.6.12
> 验证环境：独立 Microsoft Edge 用户目录、未打包扩展、GIF Lab `cadence` 动态场景

## 1. 结论

用户指出的核心问题成立：基线 Action 中的 `Record GIF` 在无障碍语义上是按钮，视觉上却更像一张浅色说明卡；下方高饱和蓝色 `Start Recording` 才被感知为主操作。

本轮已经完成四个发布闭环：

1. 让 GIF 入口在默认、悬停、按下、键盘焦点和处理中都明确表现为可执行 CTA；
2. 让选区、倒计时、录制、保存、Studio 和导出持续表达同一个“区域 GIF”任务；
3. 修复选区工具条的视口边界与键盘可达性问题；
4. 让 GIF 导出标题、循环策略和 EDM 体积提示与实际交付目标一致。

最终独立浏览器回归证明：选区、OPFS 录制、Studio 播放与导出 GIF 都保持动态；P0/P1 问题已经关闭，该垂直切片达到可发布标准。选区尺寸映射展示与细粒度错误恢复仍作为 P2 后续项保留。

## 2. 评估范围与路径

本轮使用以下真实业务路径，而不是只看静态组件：

`Action → Record GIF → 页面选区 → 确认 → 倒计时 → 区域录制 → Action 暂停/停止 → OPFS 保存 → Studio → 播放 → GIF 导出`

同时检查：

- 鼠标与键盘入口；
- 默认、处理中、选区中、录制中、保存中和失败恢复状态；
- 文案、视觉层级、状态连续性与无障碍语义；
- 选区靠近视口边界的可操作性；
- 面向落地页 / EDM 的 GIF 默认值与导出提示。

## 3. 基线证据

### 3.1 Action 默认态

- AX 树将 `Record GIF` 正确暴露为 button，Enter 可以启动选区；
- 默认视觉是浅紫背景、细边框、左图标、两行说明，没有尾部动作符号，也没有主按钮的实体感；
- 下方蓝色 `Start Recording` 对比度、阴影和面积更强，形成唯一主操作；
- 键盘焦点使用浏览器默认黑色轮廓，与组件视觉体系不一致。

### 3.2 选区态

- 页面覆盖层、尺寸反馈、重新选择、确认、Esc 取消均已存在；
- 当前提示与按钮全部硬编码为中文，而本次浏览器和 Action 为英文，出现同一任务内语言切换；
- 工具条通过 `.toolbar { bottom: -52px }` 放在选框外，同时根节点 `overflow: hidden`。选区贴近视口底部时，确认工具条会被裁掉；
- 完成拖拽后没有把键盘焦点移到确认操作，也没有 Enter 确认快捷键。

### 3.3 选区中 / 录制中的 Action

- Action 会恢复持久化状态，允许取消选区、暂停和停止，状态所有权链路正确；
- 但不可用的视频模式仍占据大部分空间，形成“禁用设置页”，而不是当前任务控制面板；
- 录制中只显示通用 `Recording`，没有说明当前是 `GIF · Area`，用户无法从 Action 复核交付意图。

### 3.4 Studio 与导出

- 停止后能自动打开带 `intent=gif` 的 Studio；
- Studio 显示 `GIF delivery`，导出默认选中 GIF、10 fps、600px 内的已有缩放档位和有限循环；
- 导出弹窗标题仍为 `Export Video`，与当前格式及主按钮 `Export GIF` 冲突；
- 有预估分辨率、帧数和大小，但没有 EDM 交付风险说明。本次 43 秒基线给出约 `5.4 MB–27.2 MB`，仍可无提示直接导出；
- 循环次数已存在于编码选项，但 UI 不可见、不可修改。

## 5. 发布验收标准与结果

### Action

- GIF 入口无需悬停也能被 5 秒内识别为可点击主操作；
- hover、pressed、focus-visible、disabled/busy 均有可见且一致的反馈；
- Enter/Space 可启动 GIF 选区；
- 选区和录制期间不展示无关的模式配置；
- 活动态明确显示 `GIF · Area`、计时和当前可执行操作。

### 选区

- 任意合法选区（包括贴近四边和全屏大选区）都能看到确认/重选；
- 拖拽完成后确认操作获得焦点，Enter 可确认，Esc 可取消；
- 覆盖层语言与扩展语言一致；
- 确认后立即进入不可重复提交状态，并清晰显示倒计时。

### Studio / 导出

- GIF 交付进入 Studio 后默认 GIF，并在弹窗标题、选中标签和主按钮上保持一致；
- 用户能看到并修改循环策略；
- 预估超过常见 EDM 图片预算时给出非阻断警告和明确优化动作（裁短、降低 FPS、降低尺寸）；
- 播放、导出和最终 GIF 均保持动态，首帧可独立理解。

以上标准均已在最终独立 Edge 配置中通过。`UI-10` 和 `UI-11` 不影响主路径完成，作为后续可观测性与信息透明度工作保留。

## 7. 外部约束依据

- [Mailchimp](https://mailchimp.com/help/about-template-images/) 对营销邮件图片建议尽量不超过 1 MB，邮件模板通常围绕约 600px 内容宽度设计；
- [Klaviyo](https://help.klaviyo.com/hc/en-us/articles/115005256968) 的邮件编辑器要求动画 GIF 小于 5 MB；
- 因平台和内容差异较大，本产品不做统一硬阻断：`≤1 MB` 标记为更适合 EDM，估算可能超过 1 MB 时提示复核，估算下限已超过 5 MB 时给出强警告。

## 8. 最终端到端证据

- Action：`Record GIF` 为高对比紫色实体 CTA；Tab 焦点落在该按钮时有品牌化焦点环，Space 能启动选区；视频区暴露为三级标题，旧入口改名为 `More recording options`。
- 选区：底边 `1289 × 155` 测试时操作条自动停靠顶部；重新选择后精确得到 `640 × 360`；Enter 确认、Esc 取消均通过。
- 活动态：Action 收敛为紧凑控制卡，持续显示 `Recording GIF area`、`GIF · AREA`、计时、暂停和停止。
- Studio：GIF 意图通过 `intent=gif` 进入 Studio；播放采样从 `F0000` 变化到 `F0099`、`F0047`，确认不是静止画面。
- 导出：弹窗标题和主按钮均为 `Export GIF`；默认 `10 fps`、`25%`、`Repeat 2 times`；8 秒裁剪估算为 `1012.5 KB–4.9 MB`，显示 EDM 复核提示。
- 最终文件：实际生成 GIF89a、`480 × 270`、`2,972,921` bytes；Edge 回放两次采样分别为 `F0088` 与 `F0069`，确认最终文件动态；最终构建的保存名为 `screen-recording-gif-<timestamp>.gif`。
